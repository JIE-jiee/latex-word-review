## 1. 执行目标

原始执行目标是从当时的“文档骨架”推进到一个可安装、可测试、可公开发布的
LaTeX–Word 审阅桥接项目。实施遵循以下硬顺序：

1. 先实测上游，再确定依赖，不重写已有转换能力；
2. 先冻结 Schema 和安全不变量，再实现流程；
3. 先证明修订账本精确，再开发审批和回填；
4. 先生成 dry-run 补丁，再允许写入工作副本；
5. 先完成 CLI 闭环，再创建 Codex Skill；
6. 先用公开合成 fixture，再用私人论文做压力测试。

## 4. E0：上游契约实验

### 任务

- E0.0 先写出 v0.1 暂定支持矩阵和自动应用安全矩阵：普通正文可候选自动回填；公式、引用、标签、编号、表格、格式修订和跨单元移动默认只入账本或转人工。实测结果可以收紧或扩展矩阵，但不得使用“尽可能支持”作为验收口径。
- E0.1 在 `build/upstream-eval/` 创建隔离环境，不全局安装依赖；记录 Python、tex2word、Pandoc、pandoc-crossref、LaTeX 和解析器精确版本。
- E0.2 生成一个中英双语最小 LaTeX fixture，覆盖正文、标题、行内/块/多行公式、标签、引用、图、子图、表、文献和多文件输入。
- E0.3 生成一个 DOCX 修订 fixture，覆盖插入、删除、替换、移动、格式修改、单点/范围批注、作者和时间。
- E0.4 实测 tex2word 的 OMML、活字段、manifest、报告、确定性输出和 Word→LaTeX reconcile。
- E0.5 实测 Pandoc/latex2word 基线的内容覆盖、交叉引用和 `--track-changes=all`。
- E0.6 对 Pandoc、`docx-revisions` 和必要的原始 OOXML 读取做同一修订 fixture 的结果比较。
- E0.7 检查许可证、维护集中度、发布和跨平台风险。
- E0.8 输出 `build/upstream-eval/results.json`、人类可读报告和 `docs/adr/0001-upstream-strategy.md`。

### 退出门槛

- 明确主转换后端、基线后端和修订解析路径；
- 每项结论都有命令、输入、输出和版本证据；
- 明确哪些缺口提交上游，哪些属于本项目；
- 没有为通过单个样本而修改私人论文或编写特例。

### 任务

- 建立 `pyproject.toml`、`src/` 包布局、`uv.lock` 和 CLI 入口；

- 建立 Windows 与 Ubuntu 基础 CI；
- 添加 `LICENSE`、`CONTRIBUTING.md`、`SECURITY.md`、行为准则和 issue/PR 模板；
- 将私人样本、运行产物、归档和环境文件默认忽略。

### 退出门槛

- 从全新环境安装构建出的 wheel 后可运行 `latex-word-review --help` 和测试；
- CI 不访问私人样本或本机绝对路径；
- 发布元数据、许可证和第三方依赖信息一致。

## 6. C2：公共 Schema 与领域模型

### 必须冻结的 v1alpha 对象

- `RunManifest`
- `SourceManifest`
- `ReviewIR`
- `SourceMap`
- `ExportReport`
- `ChangeSet`
- `ApprovalSet`
- `PatchPlan`
- `VerificationReport`

### 共同不变量

- 每个对象包含 `schema_version`；
- 所有路径使用项目相对路径，禁止泄漏本机绝对路径；
- 时间统一使用带时区的 ISO 8601；
- 文件与关键对象使用 SHA-256；
- ID 在相同基线下稳定；
- `ApprovalSet` 必须绑定 `ChangeSet` 哈希；
- `PatchPlan` 必须同时绑定基线、账本和审批哈希；
- 未知字段、兼容策略和 Schema 升级规则有明确约定。

### 退出门槛

- JSON Schema 和 Python 模型双向验证；
- 正常、缺字段、未知版本和篡改哈希 fixture 全部测试；
- CLI、HTML 页面和 Skill 都只依赖这些公共契约。

## 7. S3：环境诊断、快照和不可变运行

### 任务

- `latex-word-review doctor`：只检测，不静默安装系统依赖；
- 自动发现主 `.tex`、输入图、Bib 文件、图片和模板；
- 拒绝路径穿越、工作区外引用和危险链接；
- `snapshot` 复制到不可变 run 目录并计算哈希；
- 记录命令、配置、工具链、环境和产物；
- 支持重复运行、恢复和明确清理。

### 退出门槛

- 运行前后来源目录哈希完全一致；
- symlink、`..`、损坏压缩包和超大输入测试通过；
- 相同输入和配置生成稳定 manifest。

## 8. X4：安全导出与后端适配

### 任务

- 定义后端能力接口：OMML、活字段、引用、表格、图片、锚点、报告和 round-trip；
- 实现 `Tex2WordBackend`，只包装公共 API/CLI，不复制转换核心；
- 实现 `PandocBackend` 作为独立基线；
- 建立稳定审阅单元 `unit_id` 和 `SourceMap`；
- 将可恢复锚点写入 DOCX 书签或自定义部件；
- 统一转换指标、警告、错误码和降级项。

### 退出门槛

- 同一 fixture 可由两个后端执行并输出统一报告；
- 后端失败不会留下伪成功产物；
- 正文、公式、图表、引用和锚点均有来源计数与 DOCX 计数。

## 9. I5：DOCX 结构验收

### 任务

- 安全解包并规范化 OOXML；
- 检查 OMML 数量和图片公式降级；
- 检查 `SEQ`、`REF`、`PAGEREF`、TOC 等字段；
- 检查书签、段落 ID、关系、图片、表格和批注部件；
- 输出 JSON 与 HTML `ExportReport`；
- 建立规范化 OOXML golden tests，避免 ZIP 时间戳伪差异。

### 退出门槛

- fixture 的结构计数与期望完全一致；
- 每个不支持或降级结构都有稳定代码、位置和证据；
- 生成 DOCX 可被 Word/LibreOffice 打开且无需修复。

## 10. R6：修订/批注导入与 ChangeSet

### 任务

- 将返回 Word 原件复制到不可变归档并哈希；
- 仅在派生副本解析或接受/拒绝修订；
- 读取 `w:ins`、`w:del`、move pair、格式修订、comments 和必要的扩展部件；
- 保留作者、时间、原文、新文、批注范围和原始 XML 证据哈希；
- 将相邻删除+插入组合成替换，但保留原始事件；
- 映射 `unit_id`、源位置、匹配方法和置信度；
- 输出机器可读 `ChangeSet` 与 HTML 账本。

### 退出门槛

- canonical fixture 中每个修订事件精确出现一次；
- 对 v0.1 声明支持的事件，提取结果 precision=recall=100%；缺失元数据必须显式记录为 `null` 和诊断项，不得推测作者或时间；
- 插入、删除、移动、作者、时间和批注锚点全部与期望一致；
- 锚点损坏、重复文字和多审阅者冲突不会被错误自动定位；
- 原始 Word 哈希不变。

## 11. A7：审批状态机与本地界面

### 任务

- 先实现纯领域状态机和 CLI，再接本地浏览器界面；
- 状态包括 `pending`、`accepted`、`accepted_with_edit`、`rejected`、`manual`、`conflict`；
- 浏览器只绑定 `127.0.0.1`，不上传论文，具备会话令牌和防误提交机制；
- 对 Host、CORS、CSP、CSRF 和随机会话令牌建立自动化安全测试；
- 展示 Word 上下文、差异、作者、时间、源位置、置信度和风险；
- 支持筛选和低风险批量接受；高风险与冲突禁止批量自动应用；
- 保存版本化 `approval.json`，包含决定者、时间、原因、最终文本和账本哈希；
- Codex 与 CLI 调用同一状态机。

### 退出门槛

- 审批操作不创建或修改任何 `.tex`；
- 篡改 ChangeSet 后审批文件失效；
- 重复保存决定是幂等的，修改决定产生可追溯新版本；
- 高风险变更无法绕过核心规则。

## 12. P8：PatchPlan、dry-run 和受控应用

### v0.1 自动回填范围

只处理稳定锚点内、置信度达标的纯正文插入、删除和替换。公式、引用、标签、编号、复杂表格和跨单元移动进入 `manual`。

### 任务

- `plan` 重新校验基线、ChangeSet 和 ApprovalSet 哈希；
- 为每个批准项生成局部候选补丁和安全分类；
- 检测源文件漂移、重叠修改、编码和换行变化；
- 生成 `patch-plan.json` 与统一 `changes.patch`；
- `apply` 只写入新建工作副本；
- 支持幂等检查和失败后的完整回滚；
- 保证拒绝、待定、人工和冲突项不会进入补丁。

### 退出门槛

- 补丁内容与批准集合严格相等；
- 应用后的实际源码 diff 必须与批准补丁逐项相等，并明确报告“未批准修改数”；该值不为零即失败；
- 任何哈希漂移、定位歧义或补丁冲突都会阻止应用；
- 原来源目录和返回 Word 原件保持不变；
- 对相同计划重复运行不会重复插入内容。

## 13. V9：核验与交付

### 任务

- 使用受限参数运行 `latexmk`，禁用 shell escape 并设置超时；
- 检查未定义引用、重复标签、缺失文献、图片和输入文件；
- 生成 `revised-clean/`；
- 生成 `diff/revisions.tex` 和 `diff/revisions.pdf`；
- 可选生成基于 `changes` 宏包、区分审阅者的派生版本；
- 输出 `change-ledger.json/html` 和 `verification-report.json/html`；
- `bundle` 打包审计清单、校验和和必要交付文件，不包含私人中间产物。

### 退出门槛

- 修订后论文在支持环境成功编译；
- 已批准项、LaTeX diff 和账本能互相对账；
- 交付包包含干净版、修订标记版和完整账本；
- 所有失败都返回非零退出码和可定位报告。

## 14. H10：安全加固与开源发布

### v0.1 MVP

- 单一主后端完成公开 fixture 的完整闭环；
- Windows 和 Ubuntu clean-install 通过；

### beta

- 每个真实缺陷都有公开最小回归测试；

## 16. 测试语料递进

1. `fixture-minimal`：中英文正文、基本公式、图、表、引用；
2. `fixture-revisions`：插入、删除、替换、移动、格式和批注；
3. `fixture-anchors`：书签保留、删除、重复文本和错误定位；
4. `fixture-complex`：多文件、自定义宏、子图、长表、BibLaTeX、算法；
5. `fixture-security`：路径穿越、损坏 ZIP/XML、外部关系和资源耗尽；
6. 私有真实论文：只在公共 fixture 全部通过后做压力测试。

每个公共 fixture 必须包含来源、作者、许可证、再分发许可、生成方式、预期计数、SHA-256 和隐私扫描记录。发布前还须扫描 Word 作者/initials、评论者、公司、自定义属性、custom XML、外链、本机路径、邮箱、缩略图、隐藏文本与嵌入对象。

- 人工发行验收：Word 365 打开、修订、批注和字段刷新。
