# 开源成熟度与发布路线

## 当前成熟度

当前是公开 GitHub 上的 `0.1.0b2` beta 源代码候选，而不是阶段 0 文档骨架。本文已更新并取代早期
“尚无仓库/代码”的路线快照。工程已经具备本地 Git、`pyproject.toml`、`src/` 包、
`uv.lock`、Apache-2.0 许可证、v1alpha Schema、高层固定目录 workflow 与完整底层 CLI、
合成公开 fixture、自动化测试、Word 实机视觉/保存往返契约、发布候选门禁、GitHub Actions
配置，以及可安装 Codex Plugin 内的薄 Skill。

公开仓库身份已确认为
[`JIE-jiee/latex-word-review`](https://github.com/JIE-jiee/latex-word-review)，源代码仓库公开，
私密漏洞报告渠道已启用。项目的维护范围已经收敛为 Windows；远程 Windows 证据以
GitHub Actions 对精确提交的状态为准。当前没有 tag 或 PyPI/GitHub prerelease，因此可以
称为公开 beta 源代码候选，但不能仅凭本地测试声称获得远程 Windows 绿灯或达到 1.0。

本候选新增的成熟化边界包括：导出件确定性启用 Track Changes；返回 Word 必须通过同次
导出基线的 scoped reject-view 核验；普通正文修订可缩窄到精确 UTF-8 byte span；PDF 图片
只在派生 overlay 中转为 canonical PNG；Plugin/Skill 只编排同一核心 CLI。图片实例计数、
`verified_for_text_patch` 和 Word COM 契约均是有边界的证据，不等于任意复杂文档的视觉或
语义无损证明。

“成熟”以可复现、可审计、安全和稳定契约衡量，不以功能数量或单篇论文演示衡量。

## v0.1：安全最小闭环

必须具备：

- 现代 `pyproject.toml`、`src/` 布局、CLI、锁文件和 Git 历史；
- `doctor`、输入冻结与 SHA-256、Word 导出、返回原件归档、修订账本、待批准补丁和核验命令；
- 一个主转换后端和一个可选对照后端；
- 一个完全自制、许可明确的中英双语综合 fixture；
- 版本化 `ChangeSet` 和报告 Schema；
- 导出 Word 明确启用 Track Changes，并将图片派生 overlay、原始/派生树哈希和 manifest
  artifact 绑定进 sealed `SourceMap`/`ExportReport`；
- README、许可证、贡献指南、安全政策、issue/PR 模板；
- Windows 上从构建出的 wheel/sdist 完成 clean-install 测试。

发布硬门槛：

- 来源目录哈希在运行前后完全一致；
- 标准 fixture 中插入、删除、作者、时间和批注提取与预期一致；
- 默认 dry-run，不原地覆盖权威源；
- 所有不支持结构都有机器可读发现项；
- 所有公共样本都有来源和许可证记录；
- CI 全绿。

## beta：完整工作流和兼容矩阵

必须新增：

- 稳定后端接口及最低/最新兼容版本契约测试；
- 多文件、CJK、BibTeX/BibLaTeX、宏、复杂公式、子图、长表和多种修订组合语料；
- 锚点损坏、冲突、低置信度和恶意/损坏输入测试；
- 规范化 OOXML golden tests 和确定性输出测试；
- Windows + Python 3.12/3.13 核心 smoke test；
- Windows 上 MiKTeX、Pandoc、tex2word 和 Microsoft Word 的明确支持矩阵；
- 架构、配置、Schema、错误码、故障排查、ADR 和迁移文档；
- TestPyPI/GitHub prerelease 的端到端安装验证。
- Codex Plugin marketplace clean install，以及 canonical/embedded Skill 字节一致性和新
  Agent 前向测试。

发布硬门槛：

- 支持范围内没有未报告的内容丢失；
- canonical 修订语料全部通过；
- 所有生成 DOCX 通过结构校验；
- 固定环境和 `SOURCE_DATE_EPOCH` 下可复现；
- 路径穿越、超大解压、损坏 XML、超时和资源上限测试通过；
- 依赖许可证和漏洞扫描通过。

## 1.0：稳定公开契约

1.0 需要稳定：

- CLI 命令、退出码和配置；
- Python 公共 API；
- `ChangeSet`/`PatchPlan` Schema v1；
- 后端插件接口；
- Skill 与核心包兼容范围；
- 受支持的 Windows/Python 和 Windows/工具组合；
- 弃用、迁移、安全支持和发布政策。

发布硬门槛：

- 所有受支持 Windows/Python 组合从 wheel/sdist clean install 后端到端通过；
- canonical 账本保持精确，权威源不可变属性有自动化测试；
- 无未处置 Critical/High 漏洞；
- 有威胁模型、安全报告渠道、SBOM、第三方许可和 SHA-256；
- Tag 与 Python 包版本一致；Codex Plugin 使用合法 SemVer，并在发行说明中明确其与 Python
  prerelease/CLI 的兼容关系（不把 Plugin SemVer 与 PEP 440 字符串强行写成同一值）；
- 至少完成一次 Word 365 Windows 人工发行验收；
- 至少一个 RC 经独立环境或公开用户验证。

Linux 和 macOS 不属于 beta 或 1.0 路线图。纯 Python wheel 在这些系统上的偶然可安装性
不构成兼容承诺；若未来扩展平台范围，必须另立治理决策、阻塞 CI、支持矩阵和发行证据。

## 安全边界

LaTeX、DOCX 和压缩包均视为不可信输入：

- 禁止 `--shell-escape`；TeX/TikZ 只在复制后的受限临时目录运行；
- 子进程使用参数数组，不拼接 shell 命令；
- 限制时间、内存、进程数、文件数、输出体积和解压比；
- 拒绝路径穿越、symlink/hardlink 逃逸、DTD/外部实体和宏执行；
- 默认拒绝 `.docm`，报告外部关系和嵌入对象；
- 原始 Word 只读归档并哈希，任何变形只操作副本；
- 日志和报告可能包含论文正文，默认本地保存并提供清理策略；
- CI 的外部 PR 不得获得秘密或访问私有语料。

## 公共样本要求

公共 fixture 应尽量程序化生成，每个样本记录：

```text
source, author, license, provenance, sha256,
redistribution_allowed, contains_personal_data, reviewed_by
```

发布前扫描 DOCX 的作者、公司、时间、评论者、initials、自定义属性、custom XML、外部关系、本机路径、邮箱、缩略图、嵌入对象和隐藏文本。

真实论文、未发表数据、导师返回 Word、商业字体、出版商模板和无授权图片不得公开。
