# v0.1 暂定支持与自动应用安全矩阵

本文件是 E0 契约实验的验收输入，不是未经验证的功能承诺。实验只能用证据收紧或扩展范围；任何无法解析或无法安全定位的内容都必须形成机器可读发现项，不能静默消失。

## v0.1 用户闭环

```text
doctor → snapshot → export → inspect → archive → ingest → approve → plan → apply → verify → ledger → bundle
```

v0.1 的目标是完成一个安全、可审计的最小闭环，不是覆盖任意 LaTeX 或任意 Word 修订。

## 能力范围

| 能力 | v0.1 目标 | 自动应用资格 | 失败策略 |
|---|---|---|---|
| 普通标题和正文导出 | 支持 | 不适用 | 报告源位置和后端诊断 |
| 行内/块公式导出 | 后端能产生原生 OMML 时支持 | 无 | 图片或文本降级必须显式报告 |
| 图、表、标签、引用导出 | 支持结构核验；精度取决于后端 | 无 | 字段、编号或资源缺失必须报告 |
| `w:ins` 插入 | 精确提取文本、作者、时间和证据 | 仅稳定锚点内的普通正文 | 无法定位则 `manual` |
| `w:del` 删除 | 精确提取删除文本、作者、时间和证据 | 仅稳定锚点内的普通正文 | 删除文本缺失即契约失败 |
| 相邻删除+插入替换 | 保留原始事件并生成组合视图 | 仅稳定锚点内的普通正文 | 歧义或跨单元则 `manual` |
| Word 批注 | 提取正文、作者、时间、范围和证据 | 无；只进入账本 | 缺失元数据显式为 `null` |
| `moveFrom`/`moveTo` | 识别并入账 | 无 | v0.1 标记 `manual`；不得静默接受 |
| 格式修订 | 识别并入账 | 无 | v0.1 标记 `manual` |
| 公式、引用、标签、编号内修改 | 识别并定位到审阅单元 | 无 | 强制逐项人工处理 |
| 表格、图题和复杂块修改 | 识别并定位到审阅单元 | 无 | 强制逐项人工处理 |
| 锚点丢失或重复文本 | 提供匹配证据和置信度 | 无 | `unmatched`/`conflict`，禁止猜测应用 |
| 整篇 Word→LaTeX | 不支持 | 无 | 明确拒绝 |

## 自动应用的全部前置条件

一个变更只有同时满足以下条件，才能进入可执行 `PatchPlan`：

1. 决定状态为 `accepted` 或带明确最终文本的 `accepted_with_edit`；
2. 变更属于普通正文插入、删除或替换；
3. `unit_id` 与精确源码范围存在，且来源切片哈希匹配；
4. 定位置信度达到策略阈值，没有重复候选；
5. 不跨文件、跨审阅单元或结构边界；
6. 不触及命令、宏参数、公式、引用、标签、编号、表格结构或资源路径；
7. 与其他已批准补丁不重叠；
8. 基线、`ChangeSet`、`ApprovalSet`、planner 配置和 sealed producer 身份均未漂移。

任一条件不满足都必须 fail closed。批量接受不能改变安全等级，也不能绕过上述检查。

## 量化验收

- 对声明支持的修订类型，canonical fixture 的提取 precision=recall=100%；
- 同一输入重复 ingest 得到相同的 `change_id` 和账本摘要；
- `approve` 只产生审批数据，来源树和返回 Word 原件零字节变化；
- `plan` 只产生预览数据，不创建 `revised-clean/`；
- `apply` 只写新目录，实际 diff 与批准补丁逐项相等，未批准修改数为 0；
- 所有 unsupported、manual、conflict 和降级项均可机器读取。
